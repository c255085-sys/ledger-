# 第 2 步：確認卡與 Gemini

> 這份是給阿興看的小方案。看完覺得可以，回一句「可以」，才開始做。
> 對應排程：11/27（五）。只講四件事：這步做什麼、會動到哪些檔案、手機上看到什麼算過關、有幾件事要你先點頭。

## 一、這步做什麼

做完的樣子：**打一句話 → 看一眼卡片 → 按確認 → 記下來**。

1. 首頁多一個輸入框和一個「送出」按鈕。這步只能用打的，語音下一步才做。
2. 按「送出」會出現一張「確認卡」，卡上把這句話拆成金額、分類、備註，原句留在最上面。
3. 卡片上的金額、分類、備註都可以改；按「確認」才存，按「取消」什麼都不存。
4. 存好之後出現「已記下：午餐 120（餐飲）」，輸入框清空，可以接著記下一句。

### 分兩段做，A 段先、B 段後

- **A 段（不接 Gemini，先能手動填）**：按「送出」→ 直接跳出手動確認卡 → 自己填金額、分類、備註 → 確認入帳。整段不需要網路、不需要 key。
- **B 段（再接 Gemini）**：同一句話先送給 Gemini，讓它把卡片填好；填不好（超時、沒 key、額度用完、斷網、回傳看不懂）就退回 A 段那張手動卡，上方多一句白話原因。

**A 段全部過關之前，不碰 Gemini、不貼 key。** 這樣卡住時才分得清楚是「記帳流程寫錯」還是「API／網路／額度」的問題；B 段當天接不好也不算落後，A 段能手動記帳就算這天的核心達標。

## 二、確認卡有哪些欄位（照這個做，不要多也不要少）

| 欄位 | 能不能改 | 卡片上預設顯示什麼 | 規則 |
| --- | --- | --- | --- |
| 原句 | 不能改，但可以長按複製 | 剛剛打的那句話 | 一定留在卡上，讓阿興對照；Gemini 改了也不能蓋掉原句 |
| 金額 | 可以改 | A 段空白；B 段填 Gemini 給的 | 整數新台幣，例如 `120`；不要「120元」、不要小數 |
| 分類 | 可以改（下拉選單，六選一） | A 段停在「其他」；B 段填 Gemini 給的，對不上就「其他」 | 選單內容等第八節第 1 題點頭才寫死 |
| 備註 | 可以改 | 空白，或 Gemini 給的短句 | 可以空白，不要自己編故事 |
| 日期 | 不能改 | 今天（台灣時間） | 卡片上只顯示不給改；要補前幾天用清單的「編輯」，那是下一步 |
| 按鈕 | — | 「確認」「取消」 | 放在卡片最下面 |

多筆時，卡片上還會多一段「沒記到」的提示，位置在按鈕上方，格式看第五節。

### 卡片的行為

- 卡片出現時，游標停在金額欄，手機直接跳數字鍵盤。
- 金額不是正整數（空白、0、負數、有小數、打「120元」）→ **不給確認**，卡片上出現白話「金額要填整數，例如 120」，不要把整張卡洗掉。
- 按「取消」→ 卡片消失、什麼都沒存；輸入框裡的原句**留著**，方便改一改再送。
- 按「確認」→ 寫進瀏覽器的 `ledger-data`（格式照 CLAUDE.md 第四節）→ 出現「已記下：午餐 120（餐飲）」→ 輸入框清空。
- 寫不進去（例如空間滿）→ 要講「這次沒存成功」，不能假裝成功，卡片留著讓他重試。
- 一次只出現一張卡。這步**不做**「全部記下」按鈕，也不做多筆列表卡。
- 為了讓你在手機上能確認「真的存進去了」，卡片下面會有一行小字「這個瀏覽器目前記了 N 筆」。這是暫時的，下一步做正式清單就拿掉。

## 三、先手動、再接 Gemini 的順序

**A 段（先做，做完先給你驗）**

1. 打字 → 按「送出」。
2. 卡片馬上出現，不用等、不轉圈。
3. 金額空白、分類停在「其他」、備註空白、原句已填、游標在金額。
4. 自己填好 → 確認 → 入帳。

**B 段（A 段過關後才動）**

1. 打字 → 按「送出」→ 畫面轉圈，最多 8 秒（第四節）。
2. 拿到 Gemini 的回答 → 只取清單第一筆填進卡片 → 卡片出現，欄位照樣可以改。
3. 任何失敗 → 卡片照樣出現、切成手動，上方寫一句白話原因。
4. B 段會多一個「設定」小區塊：貼 key、儲存、清除。沒貼 key 也還能用 A 段的手動記帳。

## 四、8 秒上限（白話版）

- 計時從**按下「送出」那一刻**開始，不是等畫面轉圈才開始。
- 8 秒內沒拿到完整回答 → 放棄這次請求，卡片立刻切成手動。
- 轉圈最多 8 秒。8 秒到，畫面上一定要有卡片可以按，**不能一直轉**。
- 要真的把請求停掉（`AbortController`），不能只是把轉圈動畫藏起來、請求還在背景跑。
- 手機沒網路（例如開飛航）→ 不要送、也不要等 8 秒，直接出手動卡，訊息「現在沒有網路，先用自己填的」。
- 轉圈期間「送出」按鈕灰掉不能再按，避免連按記到兩筆；8 秒後恢復。

每一種失敗都要有自己的一句白話，不能只寫「發生錯誤」：

| 情況 | 卡片上方要寫什麼（草案，你可以改） |
| --- | --- |
| 8 秒沒回應 | Gemini 8 秒內沒回應，已切換手動輸入 |
| 沒貼 key | 還沒貼 Gemini 的 key，下面可以貼；這次先用自己填的 |
| key 不對／被撤銷 | Gemini 說這支 key 不能用，去 Google 後台確認一下；這次先用自己填的 |
| 額度用完 | Gemini 今天的額度用完了，明天再試；這次先用自己填的 |
| 沒有網路 | 現在沒有網路，先用自己填的 |
| 回傳看不懂 | Gemini 回來的內容看不懂，已切換手動輸入 |
| 其他 | Gemini 這次沒成功（原因：…），先用自己填的 |

key 不能出現在訊息、console、網址或任何檔案裡。

## 五、Gemini 回什麼、只記第一筆、沒記到的怎麼提示

**5.1 要求它回一份清單**：只回 JSON 陣列，不要加說明、不要加 Markdown 圍欄。每筆只有三個欄位：`amount`（整數）、`category`（六個分類之一）、`note`（原句裡的短詞）。就算只認到一筆，也要回長度 1 的陣列。提示詞只送那一句話，不附日期、餘額或其他資料。

**5.2 前端只認清單**：允許外層多包一層 `{"records":[...]}`，也允許被 Markdown 的 json 程式碼圍欄（三個反引號那種）包住；但**不是清單就當失敗**，走手動卡。空清單也算失敗。解析不出來不要硬猜。

**5.3 只把第一筆放上卡**，第二筆以後不上卡。清單長度大於 1 時，卡片按鈕上方要出現提示，照這個格式（數字和內容換成實際值）：

> 這句認到 2 筆，這次只記了第一筆：午餐 120。
> 另 1 筆沒有記：捷運 30。

三筆以上就是「另 2 筆沒有記：捷運 30、飲料 45」，一筆一筆列。規則：

- 每一筆都要寫出「備註 金額」，不能只寫「還有 2 筆」。
- 備註是空的時候，只寫金額。
- 這段要直接顯示在卡片上，不能收在「展開」或跳出的小視窗裡。
- 用詞要讓人一眼知道：**只有第一筆進去了**，其他要自己再記一次。

- [ ] 金額留空按確認 → 不會入帳，出現「金額要填整數，例如 120」這種白話提示。
- [ ] 填 120、分類選餐飲、備註午餐便當 → 確認 → 出現「已記下：午餐 120（餐飲）」，輸入框變空。

## 八、要你先點頭的四件事

1. **分類名稱**：卡片的分類選單要放哪幾個？先照 CLAUDE.md 第六節那六個（餐飲、交通、購物、娛樂、居住、其他）可以嗎？你說可以我才寫死進畫面；要改名、合併或刪減，現在講。
2. **key 存哪裡**：CLAUDE.md 第四節寫「localStorage 只放一個 key：`ledger-data`」，但 key 也要存在手機瀏覽器，這兩句打架。我建議另外用一個名字 `gemini-api-key` 存那串 key（不含記帳資料），並在 CLAUDE.md 補一句說明。可以嗎？
3. **超時後金額要不要帶入**：CLAUDE.md 寫「留空或帶入已解析到的值」，兩種都行。我建議一律留空，寧可空白也不要帶錯金額。可以嗎？
4. **按確認後，「沒記到」那段要不要留**：我建議留到下一句話才消失，提醒你另外那筆還沒記。可以嗎？

第 1～4 題你只回「可以」，我就照上面的建議做。
